# RynthAi 0.5.14-legacy-ui: pack items are inventory again, plus Mini Remote logging

**Date:** 2026-10-05
**Component:** RynthSuite, RynthAi plugin (`Plugins/RynthCore.Plugin.RynthAi`)
**Previous release:** 0.5.13-legacy-ui

## Problem

You couldn't add many pack items (recall gems, keys, spell components, food and other misc items) to the Mini Remote:

- Dragging or `remoteslot <slot> <id>` reported "That item is no longer in your pack."
- Clicking the item in the game inventory and assigning it put the **side pack** in the slot instead of the item.

Both symptoms had one cause. This morning's aelrynth merge (532fa67) dropped the typed-classification fix from 898bf8b. `WorldObjectCache.TryClassify` was back to accepting only weapons, armor, casters and containers as items. Every other positioned non-creature object (about 40 pack items, `ItemType` flags such as `0x800`) was filed as Unknown landscape and never as inventory. `ReclassifyUnknownDynamics` also re-probed them every 2 seconds without ever fixing them.

`HudController.PackItem` only searches inventory, so it couldn't find them. `AssignablePackItem` then fell back to the remembered selection, which was the side pack.

## Fix: classifier (port of 898bf8b)

`Combat/WorldObjectCache.cs`:

- **`TryClassify`:** any positioned non-creature object whose `ItemType` maps to a real class is classified with `ClassifyItem` and placed by the new `PlaceTypedObject` helper.
- **`PlaceTypedObject`:**
  - Portals and lifestones go to landscape.
  - Dynamic objects that the player wields, or that sit in the main pack or a side pack, go to inventory.
  - Other dynamic objects (ground drops, corpse or chest contents) go to landscape with their item class.
  - When ownership can't be read, gear types go to inventory.
  - Static non-container objects stay Unknown scenery.
- **`IsOwnedByPlayer`:** reads the wielder and container, with one nesting level for side packs.
- **`ReclassifyUnknownDynamics`:** Unknown objects whose type is now readable are collected during the pass and placed afterwards, instead of being re-probed forever. The pass logs `typed N Unknown object(s) as items (M into inventory)`. The "0 promoted" heartbeat no longer fires on passes that typed something.

## Logging: Mini Remote (`Huds/HudController.cs`, category `Huds`)

All lines go to the Huds trace (`Logs\Diagnostics\Trace\Huds_<date>.txt`) when that category is traced:

- **`HandleRemoteSlot`:** the raw value, the parsed slot and id, or a parse failure.
- **`SetSlotFromItemId`:** the id and whether it was found in inventory. When it isn't found, the line also gives the inventory count and how the world cache knows the object (for example `world cache has 'Thaelaryn Lassel Recall Gem' as Unknown`). That line would have shown this bug immediately.
- **`AssignablePackItem`** (assignments only, not the 4×/second tooltip probe): the selected id, whether it's in inventory, and whether the remembered item was used instead (which id and how old).
- **`AssignSlot` and `AddToItemHud`:** the slot, name, id, wcid and icon.
- **`Chat()`:** every message shown in game is also written to the Huds trace.
