# Merge: upstream aelrynth RynthCore 2026.10.5.1 into SK-local

**Date:** 2026-10-05
**Branch:** `merge/aelrynth-2026.10.5.1` (local only, not pushed)
**Upstream:** https://aelrynth.com/git/rynth/RynthCore (`upstream/main`, c3e1548)
**Component:** RynthCore (engine, plugin SDK, launcher, installer). RynthSuite is not part of this merge.

## Summary

Brings the upstream 2026.10.5.1 snapshot into our fork. Upstream publishes squashed
snapshots with no shared history, so the snapshot we had already ported (9b5e276,
2026.9.27.2) was recorded first as the merge base. This merge is a 3-way merge on top of it.

Upstream's architecture wins wherever the two sides overlapped. Our features were ported
into the new structure rather than kept beside it.

## What upstream brings

- **UI data hub:** panels now read from `UiSources` and act through command classes
  (`RynthAiCommands`, `ItemsCommands`, `NavCommands`, `SettingsCommands`). Plugin exports
  are bound through `PluginExportBinder` and run on the pump thread (`UiDataHub.Post`).
- **ImGui "faces":** ImGui versions of the panels (`ImGui/Panels/*Face.cs`).
- **Chat:** chat model and router in `UI/Data/ChatData.cs`, with rules that have an
  action, a "when" condition and a colour.
- **Settings:** data-driven settings (`SettingsSchema` / `SettingRow`).
- **Frame pipeline:** `EngineFrameController` replaces `ImGuiController` (deleted).
  ImGui is now drawn *before* the Avalonia overlay, so draw order matches mouse hit-testing.
- **Unloadable engine:** a CoreCLR engine hosted by a native C loader (`native/Loader`,
  `RynthCore.Shim`, app-local .NET runtime in `Runtime\dotnet`). The NativeAOT engine
  is still available.
- **Plugin API stubs:** every plugin API slot is routed through native loader stubs.
- **Decal bridge (experimental):** a Decal network filter that lets an account run as
  "Decal + RynthCore", with installer and launcher registration.
- **Item data:** a full PublicWeenieDesc byte snapshot (`PwdLayout`) for off-thread item reads.
- **Monster HUD, Lua panel**, plus many other fixes in the snapshot.

## Our features kept

- **Plugin API v77 (ABI change):** `GetMergeStackResultFn` moves to the end of the
  API struct, after upstream's v68–v76 slots. Our previous slot position collided with
  upstream's, so `PluginContract.Current`, `RynthCoreApiNative` and
  `RynthCoreHost.CurrentApiVersion` are now 77. `HasGetMergeStackResult` requires v77.
- **Plugin overlay windows:** the ILT Hub, Item Info, Lua and Map overlay windows still
  render when the ImGui shell is off. This is a new branch in
  `EngineFrameController`, using `PluginManager.HasOverlayPlugins` and the
  `EnablePluginOverlayWindows` setting.
- **Engine settings:** `LoggingLevel` is kept next to upstream's Decal settings.
  The Decal keys were added to `OwnedFields` so settings.json never gets duplicate keys.
- **Window messages:** the layered-window self-destroy message moved from 0x8005 to
  0x8051. Upstream now uses 0x8005 for `WM_RYNTH_POST_ACTION` on the game window.
- **Chat standard filters and match modes:** ported into upstream's `ChatModel` and
  `ChatRouter`.
  - Contains / Starts with / Ends with / Regex modes for each rule.
  - Standard (canned) filters run after custom rules and can hide lines or move them to a tab.
  - Both the Avalonia filters panel and the ImGui `ChatFiltersFace` have the mode picker
    and the Standard filters section.
  - Settings JSON is unchanged (`filters[].mode`, `presets[]`). `RynthChatPresets`
    state is `volatile` because routing runs on the pump thread.
- **Items panel Shields:** the Shields section is now backed by
  `ItemsCommands.AddSelectedShield` (`RynthPluginAddSelectedShield`).
- **Inventory HUDs button:** a new `SettingKind.Button` row type in `SettingsSchema`
  (Avalonia panel and ImGui face). It opens the HUD / Mini Remote window through
  `RynthAiCommands.ApplyRemoteCommand("huds", "show")`.
- **RynthAi dashboard:**
  - Char → `hub show`.
  - Hub → `remote toggle`; right-click → `huds show`.
  - The Map half of the Nav/Map button → `map toggle`.
  - All four go through `RynthAiCommands.ApplyRemoteCommand`.
- **Meta folder:** `MetaData.MetaFolder` follows the install path
  (`RynthInstallPaths.RynthAiDir\MetaFiles`) instead of a hard-coded `C:\Games` path.
- **Nav panel:** waypoint list polling pauses while the pointer is over the list.

## Dropped in favour of upstream

- `PropertyUpdateHooks` int/bool caches and `AppraisalHooks.PatchCachedInt/Bool`.
  Upstream folds property updates into its appraisal cache.
- Our duplicate PublicWeenieDesc int snapshot in `ClientObjectHooks`. Off-thread
  `TryReadPwdInt32` now reads upstream's byte snapshot via `TryGetPwdSnapshotRawInt32`.
- The deferred ImGui draw path (`RenderDeferredImGui`) and the multi-viewport experiment
  (`ViewportProbe`, `ViewportPlatformBackend`, `ViewportRendererBackend`, `ViewportOffsets`).
- The launcher's "allow multiple clients" bypass of the duplicate-session check.
  Upstream now keys sessions by account and server.

## Installer and release scripts

- `Build-Installer.ps1` keeps our layout: two install folders (`staging\core` /
  `staging\suite`), experimental plugins, Monster Editor, release package and manifest.
  New options:
  - **Default engine is now upstream's unloadable CoreCLR engine** plus the native loader
    (`scripts\Publish-EngineCoreClr.ps1`; needs the Visual Studio C++ tools).
    `-NativeAot` builds the previous NativeAOT engine and loader.
  - **Decal bridge:** built and staged to `{app}\DecalBridge` when Decal 3.0 is installed
    (or `-DecalDir`). Without Decal the build continues with a warning.
    `-IncludeDecalBridge` makes a missing Decal an error; `-SkipDecalBridge` leaves it out.
  - The required-files check also covers the CoreCLR shim and runtime, and the bridge when built.
- `RynthCore.iss`: our Suite-folder pages and publisher info, plus upstream's Decal bridge
  registration on install/update (`CurStepChanged`) and unregistration on uninstall.
- `Publish-Update.ps1`: our paths. A missing Decal bridge now only gives a warning
  instead of blocking the publish.

## Verification

- `dotnet build RynthCore.sln -c Release`: 0 errors.
- NativeAOT publish of `RynthCore.Engine` and `RynthCore.Loader`: OK.
- `scripts\Publish-EngineCoreClr.ps1` (CoreCLR engine, native loader, shim, .NET 10.0.5
  app-local runtime) to a scratch folder: OK.
- Not yet tested in game.

## Follow-ups

- RynthSuite must be rebuilt against the v77 SDK. `InventoryManager` must gate the
  merge-result call on `HasGetMergeStackResult` (v77).
- Several new upstream paths are hard-coded to `C:\Games\...` (native loader log dir,
  `RynthUpdater` default Suite dir, NavData, usage-stats dumps, ImGui pop-outs,
  Decal bridge log dir). Installs in other folders may be affected.
- The ImGui `ItemsFace` has no Shields section yet (the Avalonia Items panel does).
- The `ImGuiStackRecovery` work in the main checkout is uncommitted and not part of this branch.
