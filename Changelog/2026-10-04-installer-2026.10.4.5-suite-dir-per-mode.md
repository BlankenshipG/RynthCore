# RynthCore 2026.10.4.5: installer only reuses a RynthSuite folder from the same install mode

**Release date:** 2026-10-04
**Installer:** `installer\Output\RynthCore-Setup-2026.10.4.5.exe` (also copied to `RynthCore-Setup.exe`)
**Previous release:** `2026.10.4.4` (archived to `installer\previous-release\RynthCore-Setup-2026.10.4.4.exe`). Don't
use 2026.10.4.4 for a per-user install on a machine that also has an all-users install (see below).
**Branch:** `feat/full-installer` (local test build, not on `main`)

## Fix

To pre-fill the **Select RynthSuite Location** page, the installer used to read `Software\Rynth\SuiteDir` from HKCU **and
then HKLM**. A per-user install on a machine that already had an all-users install therefore adopted the all-users
RynthSuite folder. The two installs then shared those files, and **uninstalling the per-user install deleted the
all-users install's RynthAi DLL and Monster Editor.**

The lookup now reads only the hive of the current install mode (Inno's `HKA`: HKCU for per-user, HKLM for all-users),
matching how `GetPreviousData` and `UsePreviousAppDir` already behave. A per-user install with no per-user history
defaults to a `RynthSuite` folder next to its RynthCore folder again.

The runtime resolver (`RynthInstallPaths`: HKCU, then HKLM) is unchanged. A per-user install's own values still
take precedence for that user.

## Found by
A per-user test install of 2026.10.4.4 into a scratch folder on the build machine, which had an all-users 2026.10.4.3
install in `C:\Games`. The test install wrote into `C:\Games\RynthSuite` and its uninstall removed
`RynthAi\RynthCore.Plugin.RynthAi.dll` and the Monster Editor. Both were restored right away from the same-source build
(RynthAi 0.5.3, 217 Monster Editor files). User data folders, the experimental plugins and `C:\Games\RynthCore` were not affected.

## Also in this build
Everything from 2026.10.4.4: the .NET 10 Desktop Runtime check with automatic download and install in the installer,
and the .NET 10 SDK check with per-user auto-install in `Build-Installer.ps1`.
